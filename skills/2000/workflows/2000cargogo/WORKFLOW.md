# 2000cargogo

把汽車研究轉成主持人能快速看懂、現場發揮的拍片工作稿，直接編輯使用者指定的 Google Doc。沿用使用者認可的 Smart Fortwo 範例與 Corolla Cross 工作稿：清楚的切角、規格表、重點、討論素材、競品比較與可點來源。以繁體中文、台灣用車情境撰寫。

## 調用時先收齊兩項

每次開始**新的車款文稿任務**，先確認：

1. **本次汽車挑選**：要介紹的車款，至少品牌／車型；接受年份、動力、等級、車源頁連結或多個待挑候選車。
2. **本次 Google Doc 可編輯網址**：這次實際要寫入的目的地。

缺少時合併詢問：

> 請提供本次要整理的車款（年份／品牌／車型，或車源連結）和要寫入的 Google Doc 可編輯網址。

只補問缺少的項目。當次訊息已提供就直接採用，不重問；同一份稿的修訂、加題與續作也不重問。新任務不能自行套用歷史車款或舊目的地。若只給多個候選車，先依使用者條件協助挑選；未選定前可比較候選，不把任一台當成定稿主角。

資料未齊仍可讀寫法參考、盤點已給車源；不要在缺乏目的地時建立替代 Google Doc，或把範例文件當作寫入位置。僅在年份／動力等差異會改變結論且無法由現有資料辨認時，補問關鍵版本資訊。

## 參考與範圍

先讀 [寫法與參考文件](references/writing-format.md)。其中網址是歷史寫法／資料範例，**全部作唯讀參考，不是預設輸出目的地**。使用者另指定範例或本次偏好時，以本次指示為準。

Google 文件作業使用已安裝的 Google Drive／Google Docs 技能與連接工具。撰稿需要更貼近兩千歷史口吻時，可讀 `youtube-channel-intelligence` 的 2000CAR 寫作參考；不要因此啟動整個 YouTube 頻道爬取、逐字稿下載或影片製作流程。

預設只更新使用者給的那份 Doc。研究筆記與大量截圖可保留在本機；使用者另外提供研究 Doc 時才按指定範圍編輯。不要因流程有研究階段就自動建立第二份雲端文件。

## 固定車源與資料入口

- **公司實車先查兩千好車**：[公司網站](https://www.2000car.tw/)／[店內好車](https://www.2000car.tw/usedcar/)。使用者說「公司內的／店裡的某車款」時，先自行搜尋品牌、車名及英文別名，讀實車頁確認年份、版本、里程、配備、刊登價與狀態，不先把查找工作交回使用者。找不到或同車系有多台且無法辨識時，只補問必要資訊；可先完成其他車款。不把網站未上架解讀成店內沒有車。
- **狀態讀取注意**：網站文字擷取可能把隱藏的「已成交」標籤一併讀出；若與在庫頁或使用者資訊衝突，檢查瀏覽器實際可見標籤再判斷。跨頁搜尋、篩選與庫存皆以本次即時內容為準，不保存固定車輛清單當作未來庫存。
- **車格／規格以 [Yahoo 汽車](https://autos.yahoo.com.tw/)為主要整理入口**：優先沿用公司實車頁內的 Yahoo 汽車「車輛規格／新車價格」連結，核對台灣同年式、動力、等級與驅動。Yahoo 是規格彙整平台，稿內標「Yahoo 汽車規格」，不能稱為原廠官方公告；四驅系統、安全、保固或資料矛盾時，以原廠手冊／型錄、政府等原始資料交叉確認。Yahoo 無法讀取時註明限制，改用可核實來源，不補造規格。
- **中古行情以 [SUM 汽車](https://www.sum.com.tw/)與 [8891 汽車](https://auto.8891.com.tw/)的嚴選專區為主**：搜尋同年式、同版本及相近里程的實際車源，保留網址、查詢日期、開價、里程與嚴選／認證標記。8891 一般刊登不等於嚴選；找不到嚴選樣本時明確標示，不自行替代成嚴選行情。去除同一台跨站重複刊登、頭期款／月付價、明顯不同版本及已失效車源。樣本不足就列個案，不硬算市場區間；刊登開價不當作成交價。
- 公司實車價、Yahoo 當年新車建議價、SUM／8891 嚴選市場刊登價分開列。公司開價採本次車源頁；拍攝前由門市確認最新報價與在庫狀態。
- 使用者指定多車「各自介紹」時，按每台車的個性、使用情境、實車亮點、合理取捨與畫面逐台成段；不自動改成對決、排名或競品比較。僅整理本集真正有用的資料。
## 研究怎麼轉成內容

1. 先讀本次目的地的最新內容、tabs、原生表格與 revision；保留使用者已寫的資訊與修改。讀車源頁確認實車，再把「這一台車」與「同車款／車系」資料分開。
2. 以台灣對應年式、動力、等級為主查證；規格與保固優先原廠／政府／安全評等機構，媒體用於試駕、比較與市場解讀，論壇用於個人經驗。
3. 視題材蒐集銷量與排名、油耗／能源成本、機能配備、競品、車主心得、養車與中古車購買意義。挑能支撐本集核心問題的資料，不為湊項目硬塞歷史或缺點。
4. 把數字立即翻成買家意義：省在哪、每天何時用得到、什麼買家在意、如何影響選車。以「核心反問 → 關鍵事實 → 可以怎麼講 → 畫面／來源」形成可拍段落。
5. 保留資料來源、發布／統計時間、適用版本；查不到的價格、實測與店內故事不補造。細節見 [查證、截圖與文件操作](references/evidence-and-docs.md)。

## 撰寫預設

- **拍片工作稿，不預設長篇逐字稿。** 用短段、條列、原生規格表與競品表，讓主持人看重點就能講。可給簡短接話示例；使用者要求逐字稿時再擴寫。
- 先有好切角，再放配備；不要從冗長規格清單或研究方法開始。開場問題要由正文回答。
- 語氣像懂中古車的兩千：口語、直接、能解釋交易與日常用車的取捨。避免新聞稿堆形容詞，也不要杜撰本人賣車／試駕經驗。
- 可以用**負面表述帶出正面概念**，例如「太常見」帶出市場接受度、「太平淡」帶出日常平順。表述須有事實或實拍支撐；這是編輯切角，不冒充網友原話。
- 不為了正反平衡硬找缺點，也不把每台車都寫成無缺點。與本次版本相關、已有可靠證據的重要問題，簡明交代適用範圍及實際影響，不強行洗成優點。
- 車主原話、事實、主持人判斷、拍攝待補事項要看得出區別。競品保留真正強項，再解釋主角的選擇理由。
- 新車建議價、當期優惠、中古刊登價、實際成交價分開；「本店開價」未提供時註記依門市最新報價，內容不要依賴一個捏造的價格。

## 寫入與交付

資料足夠便完成撰稿並寫入本次指定 Doc，不只回聊天文字、本機檔或計畫，也不再詢問是否要寫入。全文格式與段落範例見寫法參考。

原生標題、條列、表格及來源超連結優先；研究資料與來源註記放在相應段落，主稿保持精簡。使用者要求截圖時嵌入真實、可讀的圖片；大量證據放指定研究文件或資料附錄，不把精簡工作稿變成截圖倉庫。

寫完讀回核對版本、表格、連結及必要圖片；涉及表格／圖片／分頁時匯出 PDF 看實際版面並修整。最後簡短說明已完成的稿件內容，附已驗證的**本次目的地**連結。不得把「檔案已產生」當成「Google Doc 已編輯成功」。
