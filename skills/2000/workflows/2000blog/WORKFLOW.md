# 2000blog

把使用者確認的兩千影片，完整轉製成 `https://www.2000car.tw/` 的可審閱文章草稿。寫台灣繁體中文；使用者要求的文章結構是：**大標題、楔子、4～5大章節、結論**，並附實際影片截圖、影片封面與完整逐字稿。

## 執行範圍與續作

- 呼叫本技能即執行本次工作；若本次只是建立／修改技能，不執行選片、下載或新增文章。
- 優先接續已登入的 YouTube Studio 與 WordPress。瀏覽器操作用可用的 browser／computer-use 技能及工具；登入失效時請使用者在該服務完成登入，不索取或保存帳密、cookies、OTP。
- 月份未指定時，月度批次以 Asia/Taipei 的**上一個完整曆月**為候選範圍，明示起訖日期；單次「最新一支」依實際上架日期選候選。不要把上傳日期、排定日期和公開日期混用。
- 月度流程每支影片仍須先確認。已確認一批明確列出的影片可逐支完成，不再逐支重問。
- 技能本身不是排程。只有使用者另要求啟用／修改每月排程時才用 Codex automation 工具，按使用者指定日期與時間建立；缺少必要時間就詢問。排程遇到候選影片時提示選片並暫停，收到答覆後續作；沒有新影片不反覆通知。

每支影片使用工作目錄 `<WORK_ROOT>\2000blog-work\YYYY-MM\VIDEO_ID\`（使用者指定位置優先）。先讀既有 `job.json` 與檔案，保存：影片 ID、標題、頻道、URL、公開日期與可見度、選片確認紀錄、處理階段、檔案與來源、疑點、WordPress post ID／編輯與預覽網址。另以 `<WORK_ROOT>\2000blog-work\index.json` 記錄影片 ID 與草稿對應，防止同月重跑或跨月重複建文；沒有紀錄也要搜尋後台確認。

## 1. 從 YouTube 後台確認選片

1. 開啟**已登入的 YouTube Studio → 內容**，核對頻道為「兩千的中古車-日榮汽車」；官網曾連結的頻道 ID 為 `UCotv4m6wWLlcP8RZsKEJAlA`，仍以當下畫面確認，不能只憑相似名稱。
2. 依指定範圍列候選：標題、影片連結／ID、公開日期、長度、影片類型及可見度。預設選已公開的一般長影片；Shorts、直播、私人、未公開、排定上架影片另列，沒有使用者指示不混入。排除已製成文章的影片；無法確認已登入後台時，公開頻道只能作候選來源，需明說。
3. 展示本支候選的標題、日期、連結、封面（可取得時），**原句提問：「請問這次是否這支來撰寫部落格文章？」選項：是／否。** 有多支時明確編號，讓使用者選擇或確認列出的一批。
4. 在這裡等待。回答「是」才下載、轉錄、寫文及建立草稿；「否」就提供下一候選或請其指定影片，不自行解讀成換另一支後直接做。無答覆不能視為同意。即使使用者直接貼影片 URL，仍保留這個選片確認步驟；同一支已在本次對話確認者不重問。

## 2. 下載音訊、封面與可截圖影片

讀取 [references/media-and-srt.md](references/media-and-srt.md)，執行其中的媒體取得、完整語音轉錄、時間對齊及截圖作業。

- 先保存影片標題、完整時長、說明、章節、公開日期、封面來源與影音版本資訊，再取得**完整音訊、原影片封面、可取畫格的完整影片**。
- 優先既有本機同版本素材；其次可用影片工具／下載器或 Studio 正常提供的下載功能。不要為此批次分析整個頻道字幕，也不匯出瀏覽器 cookie 資料庫。
- YouTube 既有字幕可作對照，不能取代本次要求的音訊轉錄。無法取得媒體或轉錄工具時，保留已完成成果並指出缺口，請使用者提供原檔或選擇可行工具，不能宣稱已有完整逐字稿。

## 3. 完整繁體 SRT

- 以原音產生全片逐字轉錄及時間碼，保留說話者原意、必要口語、數字與自我更正；只校正辨識錯字和可可靠判斷的專名，不改成文章或摘要。
- 校訂規則與可重用 SRT 格式驗證工具見已安裝的 `txttosrt` 技能，使用前讀取該技能。正常名稱包含「兩千好車、兩千中古車、兩千、阿嘎、阿宏」，仍按語境辨識。
- 從第一段有聲內容覆蓋到最後一段有聲內容；長片分段轉錄須還原全片偏移並核對接縫。不按字數估時間，不把靜音當漏字，也不把只轉錄前幾分鐘的成果標示完整。
- 不確定的車款、姓名、金額或關鍵句先回聽；仍無法確認時集中詢問，保存疑點工作稿，不能捏造後當作定稿。
- 保留 `transcript.raw.srt`、校訂完成的 `transcript.zh-TW.srt`、易閱讀的 `transcript.txt`，記錄段數、首尾時間與同步檢核結果。文章事實查核的更正另外記錄，不回填偽造原台詞。

## 4. 依官網既有文章寫完整部落格

開始撰寫及填後台前讀 [references/site-and-editorial.md](references/site-and-editorial.md) 與相鄰技能 `../2000writing/references/editorial-memory.md`。首次執行或網站有變動時，唯讀查看2～3篇近期同類文章及至少一篇後台，刷新實際欄位與版型；不修改舊文。

1. 完整讀取 SRT，建立4～5章大綱、每章對應影片時間、可截圖內容及重要事實來源。先理解全片，再下標；不只改寫影片說明。
2. 文章大標題末尾固定加上「｜兩千好車」，已有時不重複追加；SEO title 也保留此品牌結尾。大標題解決一個具體購車／養車／市場問題，車型、年份與價格有依據；楔子用反差、痛點或故事切入，交代本文要解決什麼。
3. 主體固定4～5大章，以真正的 `h2` 分章、必要時 `h3`；文章標題交由 WordPress 提供唯一 `h1`。各章用完整段落發展觀點與例子，將規格、行情和體驗轉成買家的實際影響，不以條列摘要充作完整文章，不為湊章節捏造內容。
4. 結尾標題用「結論：具體結論」，回答大標題、說清楚適合／不適合誰與實際建議；結尾內文自然呈現兩千本人分享的口吻，不把「兩千的話」另作標題。觀點與經驗必須有影片依據，不冒用其他來賓的個人經驗，也不編造兩千說過的引言。CTA 短而符合現行官網聯絡方式。
5. 首段附近嵌入確認的 YouTube 影片，沿用現有文章呈現。刪除直播招呼、無關工商、重複口吃，但不刪掉影片的關鍵條件或反方觀點。
6. 價格、促銷、庫存、保固、規格、法規等區分「影片拍攝當時」與現在。需要補充或查核時，以官方／原始資料為先並記錄日期、來源；不能把過期優惠寫成現行承諾。查核資訊與逐字稿原話分開。

## 5. 全章節實際影片圖片

- 結論至少放1張**主持人與車輛同框**的實際照片／影片畫格，另於各主章圖片之外驗收。優先清楚呈現主持人和本篇車款；背景車型無法確認就不猜車型，不以生成或合成畫面冒充實拍。
- 每一主章至少有1張直接支持該章論述的**原影片畫格**；需要對照時可多張。封面／精選圖另計，不能用一張封面代替各章圖片。
- 先由 SRT 定位，再查看前後畫面挑選，不能只按固定間隔盲截。優先清楚展示車頭、座艙、空間、配備、試駕或實際數據的畫面；避免轉場、失焦、閉眼或播放器遮擋。
- 原始擷取圖與網頁用圖都保留；網頁版不拉伸、不超解析冒充原圖，必要時轉 WebP／JPEG 壓縮。不要用生成圖、網搜圖片替代影片證據。純談話章節只能如實使用該段談話畫面，不偽稱畫面證明了未出現的規格；確實無合適畫面就揭露缺口。
- `image-map.csv` 記錄章節、檔名、影片時間碼、畫面說明、alt、caption及上傳後媒體 ID／URL。圖說自然說明重點，可附時間連結；alt 描述真正可見內容，不堆關鍵字、不猜畫面細節。
- 開啟每張最終圖片做視覺檢查，插在對應段落旁。保留影片已存在的字幕與浮水印；不為美化改變車輛或數據事實。

## 6. 內容及 SEO 完整備料

在寫入前備齊 `article.md`、可貼入的 `article.html`、`seo.json`、SRT、封面與全章節圖片。SEO 依實際 Rank Math 欄位及同類文章慣例完成：

- 文章大標題、精簡且唯一的 slug、內容摘要、分類／主要分類、作者、精選圖片。
- 1個核心搜尋意圖與焦點關鍵字，必要的自然相關詞；SEO title、meta description；社群分享標題／說明／圖片在外掛有提供時填妥。
- 每篇至少15個互不重複且與正文相關的標籤，採品牌、車型、主題、配備與實際買家問題，優先重用相關既有標籤；WordPress tags 不加 `#`。正文 hashtag 區只在同類文章確有此慣例時加，不把無關歷史標籤整包沿用。
- 自然放置關鍵字於標題、楔子、相關章節及摘要；選可用且貼題的官網內部連結、必要官方來源外部連結；不以外掛分數為由灌字、塞詞或承諾搜尋排名。
- 有外掛欄位時採合適 Article／BlogPosting 與可驗證的影片資訊；FAQ 僅在本文真的有問答時使用，不保證豐富搜尋結果。不重複新增 schema，不改全站 SEO、外掛或權限設定。

外掛沒提供、無權限或不能可靠設定的欄位，在 `seo.json` 留下待填內容及原因；不得聲稱已填。完成文章與 SEO 再進後台，避免空白／半成品被誤當完成。

## 7. WordPress 建立並驗收草稿

1. 開啟 `https://www.2000car.tw/wp-admin/edit.php`，以影片 ID／URL和標題查重，核對本機紀錄。已存在本次草稿就續作；已有發佈文不覆寫，也不默默新增重複文。結果不明或使用者正在編輯同篇時先確認。
2. 使用「新增文章」（post），不是「車輛」或「頁面」。按目前編輯器填入標題、正文、影片嵌入及連結，完整上傳本次圖檔、設定 alt／caption、精選圖、分類、標籤、摘要與實際 SEO 欄位。執行使用者已確認影片的本流程，包含為該篇上傳圖檔及存草稿，不逐欄重問。
3. 文章狀態維持「草稿」；按**儲存草稿**，不能按發佈、排程、更新既有已發佈文章或重寫並重新發佈。若下次另要求正式發佈，視為另一個明確動作處理。
4. 預覽文章，檢查標題層級、楔子、4～5章、具體結論、每章圖、圖說、播放器、連結與桌機／手機閱讀。官網目錄若顯示「找不到標題」，先檢查本文 h2／h3；若為主題或外掛問題，記錄缺口，不擅改全站版型。
5. 寫入不確定、逾時或網路中斷時先重新觀察草稿列表與媒體庫，確認是否已成功才重試，避免重複文章和圖片。更新 `job.json`、`index.json` 的 post ID、草稿狀態及網址。
6. 存檔後重新讀取確認標題末尾為「｜兩千好車」、至少15個相關標籤、結論有主持人與車輛同框結圖、正文圖片與各項設定仍存在，且狀態確為草稿。保存預覽／後台草稿畫面作驗收證據；不能只以點擊成功判定完成。
